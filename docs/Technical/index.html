5. Texniki nüanslar.

Giriş​

Son dərsimiz olaraq texniki nüanslar haqqında danışacayıq.

Niyə bunları öyrənməliyik?​

Riyaziyyat və informatika olimpiadaları arasındakı ən böyük fərqlərdən biri də informatika olimpiadalarında ideyanı tapmaqdan əlavə, onu "implement", başqa sözlə, kompüterin avtomatik yerinə yetirə biləcəyi formaya salmaq lazımdır.

Başqa bir önəmli fərq isə informatika olimpiadalarında "düsturunuzun" kompüter tərəfindən qiymətləndirilməsidir, ona görə də həddindən artıq dəqiq olmalısınız. Həqiqətən də, o, kodunuzu oxumur - sadəcə onu kompilyasiya edir, işə salır və çıxışın düzgün olub-olmadığını yoxlayır. Kiçik bir səhv (məsələn, yazı səhvi) və ya böyük bir səhv (məsələn, həll yolunuzda fundamental qüsur varsa) etməyinizdən asılı olmayaraq sizə eyni nəticəni, adətən, 0 bal verir. İnsan tərəfindən qiymətləndirmənin də dəqiq standartları olsa da, müəyyən bir məqamda onlar bir məsələdə əldə etdiyiniz anlayış və düşüncə səviyyəsini qiymətləndirməli və qazandığınız xalların sayını müəyyən etmək üçün müəyyən dərəcədə subyektiv mühakimədən istifadə etməlidirlər.

Bu səbəbdən, rəqabətcil bir proqramçı olmaq üçün, istifadə etdiyiniz alətləri (kompüterinizi və proqramlaşdırma dilinizi) daha dərin səviyyədə başa düşməyiniz daha vacibdir. Proqramçılar proqramlaşdırma bacarıqlarını mənimsəməyi öyrəndikcə, daha uğurlu olmaları qeyri-adi deyil; onlar nəinki daha sürətli kod yazırlar, həm də kod yazmağa daha az vaxt sərf etməlidirlər ki, bu da həll yolları haqqında düşünmək və daha çox problemi həll etmək üçün daha çox vaxt və enerji deməkdir. Bunu müəyyən dərəcədə yaşamış ola bilərsiniz; Əgər əvvəllər də proqramlaşdırma ilə məşğul olmusunuzsa, yəqin ki, artıq başladığınız vaxtdan daha yaxşı bir proqramçısınız. Hətta indi daha sürətli kod yazma bacarığına sahib olmuş ola bilərsiniz! Bununla belə, hələ öyrənməli olduğunuz çox şey var.

Əlbəttə ki, tətbiq bacarıqlarınızı inkişaf etdirməyin ən effektiv yolu praktikadır. Amma bir məqamda, həqiqətən də, sadəcə oturub daha incə texniki detalları oxumalısınız - hər şeyi sadəcə təcrübə və "sınayıb-yanılmaq" yolu ilə öyrənə bilməzsiniz. Bu texniki məsələlərdən bəziləri qeyri-intuitiv, bəziləri isə nadir hallarda görülür.

Keş-yaddaş və RAM​

Aşağıdakı kodu işə saldığımızda:

#include <bits/stdc++.h> 
using namespace std; 

const int cities = 5000; 
const int skylines = 20000; 
int arr[cities][skylines]; 

int main(){ 
  // bu hissə sadəcə massivin içini  
  // random elementlərlə doldurmaq üçündür. 
  mt19937 rng(11); 
  for(int i = 0; i < cities; i ++){ 
    for(int j = 0; j < skylines; j ++){ 
      arr[i][j] = uniform_int_distribution<int>(0, 100)(rng); 
    } 
  } 

  // sadə prefix sum kodu (https://usaco.guide/silver/more-prefix-sums?lang=cpp) 
  for(int i = 1; i < cities; i ++){ 
    for(int j = 1; j < skylines; j ++){ 
      arr[i][j] += arr[i][j - 1] + arr[i - 1][j] - arr[i - 1][j - 1]; 
    } 
  } 
}

Bu kod "-O3" pragması ilə işə salındıqda təxmini olaraq 0.891 saniyəyə icra olunur. Lakin prefix sumda for looplarının sırasını dəyişdiyimizdə:

for(int j = 1; j < skylines; j ++){
  for(int i = 1; i < cities; i ++){
    arr[i][j] += arr[i][j - 1] + arr[i - 1][j] - arr[i - 1][j - 1];
  }
}

Yenə də eyni şeyi edirik, elə deyilmi? Kağız üzərində eyni şeyi etsək də, bu kodu işə saldığımızda kod 2 saniyədən daha uzun bir müddətə icra olunduğunu görə bilərik. Bəs nə baş verdi ?

Əslində baş verən sadəcə keş-yaddaşın işə daxil olmağıdır. Keş-yaddaş kompüter mühəndisləri tərəfindən təkmilləşdirilən yaddaş optimizasiyasıdır. Onlar gördülər ki, CPU hər dəfə bir informasiyaya ehtiyacı olduqda o informasiyanı gedib RAM-dən götürməli olur. Əvəzinə, onlar CPU-ların daxilinə yerləşdirilə bilən keş-yaddaş adlı daha kiçik ölçülü, amma daha sürətli bir yaddaş növü icad etdilər.

Kodunuz əslində keş-yaddaşla "əlləşməli" deyil. Sadəcə, kodunuzun sürətini optimizasiya etmək üçün bu haqda da düşünməlisiniz.

Keş-yaddaşdan necə effektiv şəkildə istifadə etmək olar?​

Bunun üçün ilk öncə keş-yaddaşın necə işlədiyini anlamaq lazımdır. Proqram RAM-ın bir hissəsinə daxil olduqda, həmin RAM hissəsini keş yaddaşına kopyalayır və bunun əvəzinə keş yaddaşından istifadə edir. Bu şəkildə, proqram yenidən həmin RAM hissəsinə daxil olmağa çalışarsa, o, artıq keş yaddaşında ola bilər, ona görə də ona daxil olmaq daha sürətlidir. Əgər keş doludursa, yer boşaltmaq üçün keşdəki hissələrdən biri atılır. Hansı hissəni atacağını özü ağıllı şəkildə müəyyən edərək keşdəki itkilərin sayını azaltmağa çalışır. Məsələn, keşdəki ən az istifadə olunmuş hissəni atmağa çalışa bilər.

Keş-yaddaş və RAM-ın bitişik hissələrinin ona yüklənməsi səbəbindən, yaddaşa daxil olma ardıcıllığı keşə daxil olma və buraxılma sayına təsir göstərir və beləliklə, proqramınızın işləmə müddətinə təsir göstərir, ki bu təsir bəzən gözə çarpacaq dərəcədə də ola bilər.

Qeyd:

  • Bir massivə təsadüfi qaydada daxil olmaq, onlara ardıcıllıqla daxil olmaqdan xeyli yavaş ola bilər.
  • 2D (və ya 3D və s.) massivlərə daxil olduqda sətir-sətir access sütun-sütun access-dən daha sürətli ola bilər.

Tapşırıq 1: Qeydləri isbat etməyə çalışın.

Keş yaddaşının ölçüsü proqramın işləmə müddətinə kəskin şəkildə təsir göstərə bilər. Məsələn, keş yaddaşının ölçüsündən bir az aşağı olan massiv keş yaddaşına tam yüklənə bilər, lakin keş yaddaşının ölçüsündən bir az yuxarı olan bir qədər böyük massiv yüklənə bilməz, buna görə də daha çox keş yaddaşı itkisi olacaq və yavaşlama təxmin etdiyimizdən daha əhəmiyyətli ola bilər. Lakin olimpiadada bu qədər dərin düşünməyə gərək yoxdur, çünki yoxlayıcı kompüter(judge) hamı üçün eyni resurs istifadəsinə icazə verir.

Olimpiada üçün nəticə: Keşin mövcud olduğundan xəbərdar olun. Bunu nəzərə alaraq kod yazın. Bununla belə, unutmayın ki, bu, əsasən daimi optimallaşdırmadır, ona görə də ilk növbədə bu barədə düşünməməlisiniz – nəticədə daha vacib olan kodunuzun doğru olmasıdır.

Constructorlar​

Deyək ki, aşağıdakı kimi bir kod yazmısınız:

#include <bits/stdc++.h>
using namespace std;

struct Skyline{
  string name;
  int height;

  Skyline(string skyline_name, int skyline_height){
    name = skyline_name;
    height = skyline_height;
  }
};
struct Person{
  string name;
  Skyline address;

  Person(string person_name, Skyline person_address){
    name = person_name;
    address = person_address;
  }
};

int main(){
  Person p("Əli", Skyline("Ev", 150));
}

İkinci sətirdə gördüyümüz kimi problem Skyline::Skyline() deyilən constructorun tapa bilməməsidir. Çünki biz Skyline address; yazdığımızda, içinə heçbir dəyər göndərmirik. Bunun qarşısını almaq üçün kodu bu şəkildə dəyişə bilərik:

struct Person{
  string name;
  Skyline address;

  Person(string person_name, Skyline person_address) : address(person_address){
    name = person_name;
  }
};

Burada olan fərq əvvəlki kodda "address" constructorunu yaradıb sonradan başqa constructora mənimsətmək yerinə, birdəfəlik "person_address"-ə mənimsətməkdir. Yaxşı, bəs onda address(person_adress) niyə işləyir? Axı biz heçbir yerdə bu haqda constructor yazmamışıq? Görünüşə görə, C++ kodlandığında bunu düşünüb əvvəlcədən əlavə ediblər, yəni bunun üçün narahat olmağa ehtiyac yoxdur.

Kodunuzu daha səliqəli etmək üçün belə bir sadələşdirmə də edə bilərsiniz:

struct Person{
  string name;
  Skyline address;

  Person(string person_name, Skyline person_address) : address(person_address), name(person_name) {}
};

Hətta, funksiyanın içinə göndərdiyiniz dəyişənin adı ilə mənimsədəcəyiniz dəyişənin adını eyni qoya bilərsiniz!

struct Person{
  string name;
  Skyline address;

  Person(string name, Skyline address) : address(address), name(name) {}
};

Narahat olmayın, bu formada etdiyinizdə kompilyator nə etmək istədiyinizi başa düşür və beləliklə daha səliqəli və anlaşıqlı kod yazmış olursunuz!

Default Arguments (Defolt Qiymətlər)​

Kodu daha da anlaşıqlı və dəqiq etmək üçün nə etmək olar? Dəyişənlərə defolt qiymətlər verə bilərsiniz! Bu, həm də sizə daha rahat kod yazmağınıza kömək edəcək. Gəlin aşağıdakı nümunəyə baxaq:

#include <bits/stdc++.h>
using namespace std;

void special_print(string s, string sep, string end){
  for(int i = 0; i < s.length(); i ++){
    cout << s[i] << sep;
  }
  cout << end;
}
int main(){
  special_print("ilikecoding", "", "\n");
  special_print("ilikegames", " ", "\n");
  special_print("ilikeschool", "  ", "\n");
}

Hər dəfə "end" dəyişəninin qiymətinin "\n" olmasına baxmayaraq, biz onu hər dəfə yazmalı oluruq. Lakin belə dəyişsək:

#include <bits/stdc++.h>
using namespace std;

void special_print(string s, string sep, string end = "\n"){
  for(int i = 0; i < s.length(); i ++){
    cout << s[i] << sep;
  }
  cout << end;
}
int main(){
  special_print("ilikecoding", "");
  special_print("ilikegames", " ");
  special_print("ilikeschool", "  ");
}

Gördüyünüz kimi, kod daha sadə oldu, və biz istədiyimiz zaman "end" dəyişəni üçün də qiymət göndərə bilirik!

Tapşırıq 2: Yuxarıda gördüyünüz kodun məqsədi s sətirindəki hər bir hərfin arasına sep sətirini əlavə edib ən sona da end sətirini əlavə etməkdir. Lakin kodda səhv var. Səhvi tapıb kodu yenidən yazmağa çalışın.

Operator overloading​

C++ da standart olaraq olan işarələrin nə etdiyini dəyişə bilərsiniz! Bu işarələrə "+", "-", "*", "/", "%" və daha çoxu aiddir.

#include <bits/stdc++.h>
using namespace std;

struct num{
  int x;
  num(int x) : x(x) {}

  num operator+ (num other){
    return num(x + other.x);
  }
};

int main(){
  num a(71), b(29);
  num c = a + b; // c = num(100)
}

Tapşırıq 3: Modint adında bir struct düzəldin. Bu struct normal ədəd kimi işləməli amma hər zaman dəyəri 10^9+7 -yə qalığına bərabər olmalıdır. Qeyd: "long long" tipi ilə işləməyə çalışın, çünki böyük ədədlərlə işlədikdə problemlər yarana bilər.

Bonus: DRY prinsipi​

DRY, vəya "özünü təkrarlamama" prinsipi təkcə competitive programming-də yox, həm də ümumi proqramlaşdırmada faydalı bir prinsipdir. Vikipediyada bu, "Hər bir biliyin bir sistem daxilində tək, birmənalı və səlahiyyətli bir təmsilçiliyi olmalıdır" kimi qeyd olunur. Lakin bu, o qədər də diqqətçəkən deyil.

  • Əgər özünüzü kodu kopyalayıb-yapışdırdığınızı (və hər bir kopyanı bir az dəyişdirdiyinizi) hiss edirsinizsə, bu, səhv bir şey etdiyinizin göstəricisidir. Bu cür təkrarlanan kod adətən olimpiada üçün əlverişsiz olur; redaktə etmək daha çətindir və daha çox vaxt aparır, daha çox səhvə meyillidir və proqramınızı şişirdir, bu da oxunmasını çətinləşdirir. C++ dilində bunun qarşısını almaq üçün müxtəlif "alətlər" var: dövrlər, funksiyalar, lambdalar və s. Bunlardan lazımlı qədər və doğru şəkildə istifadə edin.
  • Eyni constant dəyərləri hər dəfə yazmaqdansa const int MOD = 1'000'000'007; kimi yazmağa çalışın.
  • Kodunuzda #define-ları mümkün qədər az işlədin. Bu həm kodunuzu səliqəsiz, həm də anlaşılmaz hala gətirir.
