Dərs 2. STL kitabxanası. Rekursiyalar.

STL kitabxanası​

Birinci hissədə C++ Standart Template Library və ya qısaca STL haqqında məlumat əldə edəcəyik. STL, proqramlarınızda istifadə edə biləcəyiniz bəzi faydalı ümumi məlumat strukturları və alqoritmləri ehtiva edir ki, bunları özünüz tətbiq etməyə vaxt sərf etməyəsiniz və beləliklə kodunuzu daha qısa edəsiniz və beləliklə problemlərinizi daha sürətli həll edəsiniz. STL texniki olaraq sadə C++ dilinin bir hissəsi deyil, lakin onlar C++-ın demək olar ki, hər yerində mövcud olduğundan, əksər hallarda onları dilin bir hissəsi kimi düşünə bilərsiniz.

Vikipediyaya görə, real dünya kitabxanası "müəyyən bir icma üçün istinad və ya borc almaq üçün əlçatan olan məlumat mənbələri və oxşar resurslar toplusudur". Yəqin ki, həyatınızda bir kitabxanadan kitablar götürmüsünüz. Proqramlaşdırmada kitabxananı müəyyən bir proqramlaşdırma dilinin bütün istifadəçilərinə (yəni siz) təqdim edilən kod toplusu kimi düşünə bilərsiniz ki, bu istifadəçilər (yəni siz) bu kod parçalarını borc ala və ya proqramlarına daxil edə bilsinlər. Beləliklə, onları özünüz yazmaq məcburiyyətində qalmayacaqsınız. Beləliklə, təkəri “yenidən icad etməyinizə” ehtiyac qalmayacaq. Normalda, bu kolleksiyalar bir çox proqramda faydalı olmaq üçün kifayət qədər ümumi olan, lakin bütün proqramlarda faydalı olmaq üçün kifayət qədər ümumi olmayan ümumi funksionallıq üçün koddur, buna görə də onlar dilin bir hissəsi deyil, ayrıca daxil edilməlidir. Batareyası olmayan oyuncaqlar kimi, C++ da belədir! (C++ standart kitabxanası iostream-dən istifadə etmədən hətta oxuya və çap edə bilməzsiniz.)

Söz düşmüşkən, siz artıq fərqinə varmadan C++ standart kitabxanasından istifadə etmisiniz. Əgər nə vaxtsa #include <iostream> əmrini verib cin və cout əmrlərindən istifadə etmisinizsə, deməli, C++ standart kitabxanasından istifadə edirsiniz. Ümumiyyətlə, C++ kitabxanasından funksiyaları daxil etmək üçün C++ faylınızın əvvəlinə #include <kitabxana adı> yazmalısınız.

Nəzərə alın ki, bu, potensial olaraq bir çox kitabxana daxil edəcəyiniz deməkdir ki, bu da çətin ola bilər (və kitabxananın adını xatırlamırsınızsa, əsəbiləşdirici ola bilər). Xoşbəxtlikdən, bütün standart kitabxananı daxil etmək üçün qısa yol var:

#include <bits/stdc++.h>
using namespace std;

Olimpiada üçün bu daha rahatdır, çünki sizə lazım olan xüsusiyyətləri olan dəqiq kitabxanaları yadda saxlamağa ehtiyac yoxdur. Lakin, bu, kompilyasiya prosesini bir az yavaşladır. Xoşbəxtlikdən, bu, faktiki proqramın işləmə müddətinə o qədər də təsir etmir, ona görə də “competitive programming” məqsədləri üçün bunu həmişə etmək yaxşı bir fikirdir. Bundan sonra, bunun edildiyini güman edəcəyik və daxil ediləcək dəqiq kitabxana adını deməyə heç vaxt vaxt sərf etməyəcəyik. (Təbii ki, istəsəniz özünüz axtara bilərsiniz). “Standart” sadəcə o deməkdir ki, bir dəstə adam kostyum geyinərək bir araya gəlib bəzi kitabxana funksiyalarının o qədər faydalı olduğuna qərar veriblər ki, bütün C++ istifadəçiləri onların hər C++ versiyasına daxil etmələrini istəyirlər. Bu o deməkdir ki, kompüterinizə yaxşı bir C++ kompilyatoru quraşdırdığınız zaman bu funksiyaların artıq quraşdırıldığına etibar edə bilərsiniz.

Riyazi funksiyalar​

“cmath” kitabxanası, elmi kalkulyatorda tez-tez rast gəlinən bir dəstə faydalı riyazi funksiya və daha çoxunu ehtiva edir. #include <cmath> etdiyiniz zaman, standart C++ kalkulyatorunuzu sehrli şəkildə elmi C++ kalkulyatoruna çevirmək kimidir ki, daha əyləncəli işlər görə biləsiniz. cmath kitabxanası texniki olaraq C kitabxanasıdır və C++ STL-nin bir hissəsi deyil, lakin bu, o qədər də vacib deyil. (Həmçinin, bütün STL-i artıq daxil etdiyimiz üçün onu açıq şəkildə #include etməyinizə ehtiyac olmadığını unutmayın.)

Pair-lər​

Pair sadəcə iki dəyişəni bir yerdə tutan data tipidir. Pair dəyişəninin yazılışı pair<Tip 1, Tip 2> pair_name; kimidir, burada Tip 1 pairin birinci üzvünün növü, Tip 2 isə pairin ikinci üzvünün növüdür. Pair yaratmaq üçün sadəcə make_pair funksiyasından istifadə edin. Cütlüyün ilk üzvünü əldə etmək üçün cütlüyə pair_name.first yaza bilərsiniz. Pairin ikinci üzvünün necə alınacağını yəqin ki, təxmin edə bilərsiniz.

#include <bits/stdc++.h>
using namespace std;

int main() {
  pair<int, int> coordinate = make_pair(1, -1);
  cout << coordinate.first << " " << coordinate.second << '\n'; // 1 -1

  coordinate.first = 2;
  cout << coordinate.first << " " << coordinate.second << '\n'; // 2 -1

  pair<string, int> name_age = make_pair("Samir", 20);
  cout << name_age.first << ", " << name_age.second << '\n'; // Samir, 20

  pair<pair<int, int>, int> nested_pair = make_pair(make_pair(1, 2), 3);
  cout << nested_pair.first.first << " " << nested_pair.first.second << '\n'; // 1 2
  cout << nested_pair.second << '\n'; // 3
}

Pairlər yaratmaq üçün bir az daha rahat bir sintaksis mövcuddur (baxmayaraq ki, bəzən kompilyator bunu rədd edir və make_pair istifadə etməlisiniz) və aşağıda göstərilən kimi yazılır:

#include <bits/stdc++.h>
using namespace std;

int main() {
  pair<int, int> lattice_point = {1, -1};
  cout << lattice_point.first << " " << lattice_point.second << '\n'; // 1 -1

  auto [x, y] = lattice_point;
  cout << x << " " << y << '\n'; // 1 -1

  return 0;
}

Vector-lar​

Massivlər əladır, lakin onlar sizdən maksimum ölçüsü əvvəlcədən göstərməyinizi tələb edir. Bu maksimum ölçünü proqnozlaşdıra bilmədiyiniz hallarda, ölçüsünü tələb olunduqda dəyişdirərək ehtiyac duyduğunuz qədər element əlavə etməyə imkan verən bir datatipə ehtiyacınız olacaq. Bunun bir yolu “linked list” vasitəsilədir. Lakin linked list-in ciddi bir çatışmazlığı var: siyahının ortasından elementləri əldə etmək üçün O(n) vaxt tələb olunur. Buna görə də, linked listlər əlverişli vasitə deyil.

Xoşbəxtlikdən, C++ dilinin daxili dinamik massivi var. Buna “vector” deyilir. Massivlər kimi, vectorlara da istədiyiniz növü mənimsədə bilərsiniz. Tam ədədlərin vektorları, pair-lərin vektorları, hətta vektorların vektorları və vektorların vektorlarının vektorları ola bilər. Baxmayaraq ki, son iki halda, çoxölçülü massivlərlə işləmək daha asandır. Vectorlar əslində arxa planda müəyyən ölçülü arraylər toplusudur: lazım olduqda, yeni arraylər əlavə olunur.

Vector funksiyaları və əlavə məlumatlar üçün bura baxa bilərsiniz.

Önəmli fakt: Deyək ki v adında int tipində vectorumuz var. v.clear() əvəzinə vector<int>().swap(v) yazmaq kodunuzu sürətləndirə bilər.

Tapşırıq 1: Bunun səbəbini izah edin.

Stack-lər, Queue-lər, Deque-lər​

Stacklər, queue-lər və deque-lər linked listlərin və vektorların məhdud versiyalarıdır və burada massivin yalnız bir və ya hər iki ucuna daxil ola, əlavə edə və silə bilərsiniz. Niyə məlumat strukturunun daha məhdud versiyasını istəyərdiniz? Səbəblərdən biri, niyyətinizin ortadakı elementlərə təsadüfi daxil olmaq əvəzinə, yalnız siyahının sonlarında işləmək olmasıdır. Həmçinin, niyyətiniz yalnız sonlardan elementlərə daxil olmaq olduğu halda, təsadüfən ortadakı elementlərə daxil olsanız baş verə biləcək səhvlərdən də qaçınırsınız. Bu data strukturları ilə qraf alqoritmləri arasında da çox gözəl bir əlaqə var ki, bunu burada görə bilərsiniz.

Vectorda olan fakt bu data tiplərə də şamil olunur.

Priority queue​

Priority queue-lər hər bir pop əməliyyatında ən uzun müddət növbədə olan elementə daxil olmaq və ya onu silmək əvəzinə, ən yüksək "prioritet"-ə malik elementə daxil olduğumuz və ya sildiyimiz queue növüdür. Prioritet qaydası istədiyimiz hər hansı bir şey ola bilər. Əvvəlcə ən yüksək dəyər, sonra isə ən aşağı dəyər və ya başqa bir qayda ola bilər. Bunu massivlər və ya vectorlarla da tətbiq etmək olduqca asandır. Amma, daxil etmə, sonra isə daxil olma və silmə O(n) vaxt aparır. Əgər çoxlu əməliyyat yerinə yetirməli olsaq, bu, çox yavaş olur. C++-ın priority_queue datatipi hər əməliyyatı O(lg n) vaxtında yerinə yetirir ki, bu da daha sürətlidir. Varsayılan olaraq, priority_queue elementləri əvvəlcə ən yüksək dəyərə görə prioritetləşdirir.

Priority queue haqqında daha ətraflı buradan və buradan oxuya bilərsiniz.

Önəmli fakt: Əgər priority queue-nün içində eyni elementdən iki dənə olarsa, onlardan hansının daha əvvəl gələcəyini bilmək mümkün deyil(ən azından competitive programmingdə)

Set və Map​

Vectorlar və massivlər elementlərin indeksləşdirilmiş kolleksiyalarıdır. Əgər elementlərin mövqeləri ilə maraqlanmırsınızsa, əvəzinə elementlərin və ya “key”-lərin mövcudluğunu tez bir zamanda yoxlamaq istəyirsinizsə, onda bunun əvəzinə set-dən istifadə edə bilərsiniz. Set sizə elementlər toplusunu saxlamağa və kolleksiyanızda müəyyən bir açarın olub olmadığını tez bir zamanda müəyyən etməyə imkan verir. Map-lər set-lərə bənzəyir, lakin yalnız “key”-ləri saxlamaqla yanaşı, hər bir “key” ilə əlaqəli bir dəyəri də saxlaya bilərsiniz. “Key” axtardığınız zaman, map özündə əvvəlcədən bu “key”-dən olub olmadığını da deyə bilir. Map-i bir massivin ümumiləşdirilməsi kimi düşünə bilərsiniz, burada 0-dan (n − 1)-ə qədər tam ədədləri obyektlərə əlaqələndirmək əvəzinə, simvolları, sətirləri və ya istənilən ixtiyari tipi obyektlərə əlaqələndirirsiniz. Map-lər həmçinin seyrək massivlər kimi də istifadə edilə bilər, burada n elementi 0-dan N − 1-ə qədər "mövqelərdə" saxlaya bilərsiniz, başqa sözlə, yalnız O(n) yer istifadə edərək O(N) aralığı istifadə edə bilərsiniz. Əgər n << N olarsa, bu, əhəmiyyətli bir qənaətdir və sizə əhəmiyyətli subtasklar qazandıra bilər.

Set-lər haqqında isə daha ətraflı buradan oxuya bilərsiniz.

Maraqlı fakt: Set-lər və Map-lər ikili axtarış ağacları istifadə edilərək tətbiq olunduğundan, onlarla əslində başqa bir maraqlı şey edə bilərsiniz: O(lg n) zaman səmərəliyində verilən sorğu açarına ən yaxın açarı tapmaq. Bunun üçün iki variant var: upper_bound və lower_bound. Kod nümunələri üçün bura və bura baxa bilərsiniz.

Önəmli fakt: Yuxarıdakı səbəbdən, əgər map və set-lərin(həmçinin, priority queue-lərin) içində struct(bunun haqqında buradan oxuya bilərsiniz) işlətmək üçün comparator(xüsusi müqayisə funksiyası) yazmalısınız. Buna çox nadir hallarda ehtiyacınız olacaq. Amma məhz bunu çox nadir hallarda etdiyimiz üçün unutmaq çox asandır. Bəlkə də qraflar dərsi sizə bunu bir daha xatırladacaq.

Tapşırıq 2: İteratorlar və burada danışmadığımız digər data tiplər haqqında qısa məlumat toplayıb discordda müzakirə et.

Sorting and Searching​

O(n^2) sorting​

Ən çox istifadə olunan iki O(n^2) alqoritm var:

  • Selection Sort
  • Insertion Sort

Selection sort​

Selection sortda sadəcə hər dəfə ən kiçik elementi götürüb massivin əvvəlinə atıb bu dövrü massivin qalanı ilə davam etdiririk.

​

Insertion sort​

Insertion sort oxşardır, çünki siyahını çeşidləyərkən qismən çeşidlənmiş siyahını prefiks kimi saxlayır. Lakin bu ssenaridə biz dəfələrlə növbəti çeşidlənməmiş elementi götürüb çeşidlənmiş prefiksdə hara getdiyini axtarırıq.

​

Təbii ki də, sadəcə iki sorting alqoritmi yoxdur. Bunlardan başqa shaker sort, odd-even transportation sort, gnome sort kimi alqoritmlər də var. Lakin bu alqoritmlərə competitive programming-də rast gəlinmədiyi üçün öyrənməyinizə ehtiyac yoxdur.

Tapşırıq 3: Selection sort və Insertion sortu implement etməyə çalışın.

O(n lg n) sorting​

O(n^2) alqoritmlər competitive programming üçün çox yavaş olduğundan praktikada biz qat-qat sürətli bir zaman səmərəliyi olan O(n lg n) müddətə işləyən “Merge Sort” alqoritmindən istifadə edirik.

​

Bəs STL kitabxanasındakı sort() funksiyası hansı alqoritmi istifadə edir? Bu funksiya introsort adlı bir alqoritm istifadə edir, hansı ki, Quicksort ilə başlayan, rekursiya dərinliyi limitləri aşıldıqda (ən pis ssenarilərdən qaçınmaq üçün) Heapsort-a keçən və kiçik alt seqmentlər üçün Insertion Sort-dan istifadə edən hibrid alqoritmdir(bu alqoritmləri də bilmək məcbur deyil, lakin əlavə məlumat olaraq qeyd olunub).

Rekursiya​

Rekursiya Nədir?​

Ümumi kontekstdə rekursiya sadəcə bir şeyin özünə aid olmasıdır. Məsələn, riyaziyyatda nnn-in faktorialı, 1-dən nnn-ə qədər bütün müsbət tam ədədlərin hasili kimi müəyyən edilir, məsələn, 5!=1⋅2⋅3⋅4⋅5=1205! = 1 \cdot 2 \cdot 3 \cdot 4 \cdot 5 = 1205!=1⋅2⋅3⋅4⋅5=120, lakin rekursiya ilə də təyin edilə bilər:

n!={1if n=0(case 0)n⋅(n−1)!if n>0(case 1)n! = \begin{cases} 1 & \text{if } n = 0 \quad \text{(case 0)} \\ n \cdot (n-1)! & \text{if } n > 0 \quad \text{(case 1)} \end{cases}n!={1n⋅(n−1)!​if n=0(case 0)if n>0(case 1)​

Qeyd edək ki, 1-ci halda n!n!n! (n−1)!(n-1)!(n−1)! ifadəsi ilə təsvir olunur. Həmçinin, 0-cı hal base case adlanır. Bu halda, bu, faktorialı tam və birmənalı şəkildə təsvir edir. Məsələn,

5!=5⋅4!=5⋅4⋅3!=5⋅4⋅3⋅2!=5⋅4⋅3⋅2⋅1!=5⋅4⋅3⋅2⋅1⋅0!=5⋅4⋅3⋅2⋅1⋅1=120\begin{aligned} 5! &= 5 \cdot 4! \\ &= 5 \cdot 4 \cdot 3! \\ &= 5 \cdot 4 \cdot 3 \cdot 2! \\ &= 5 \cdot 4 \cdot 3 \cdot 2 \cdot 1! \\ &= 5 \cdot 4 \cdot 3 \cdot 2 \cdot 1 \cdot 0! \\ &= 5 \cdot 4 \cdot 3 \cdot 2 \cdot 1 \cdot 1 \\ &= 120 \end{aligned}5!​=5⋅4!=5⋅4⋅3!=5⋅4⋅3⋅2!=5⋅4⋅3⋅2⋅1!=5⋅4⋅3⋅2⋅1⋅0!=5⋅4⋅3⋅2⋅1⋅1=120​

Proqramlaşdırmada isə rekursiya funksiyanın özünü çağırmasıdır. Məsələn, bir dövr ilə faktorial tətbiq edə bilərik:

long long factorial(int n){
  long long ans = 1;
  for(int i = 1; i <= n; i ++){
    ans *= i;
  }
  return ans;
}

Amma biz bunu rekursiyadan istifadə edərək, eyni funksiyanı öz daxilində çağıraraq da həyata keçirə bilərik, məsələn:

long long factorial(int n){
  if(n == 0){
    return 1;
  } else{
    return n * factorial(n - 1);
  }
}

Baxın, bu, yuxarıdakı tərifə nə qədər bənzəyir! Yeri gəlmişkən, rekursiv funksiyanızda həmişə base case-in olduğundan əmin olun, əks halda, funksiya proqramınız “Segmentation Error” səbəbindən çökənə qədər özünü təkrar-təkrar çağırmağa davam edəcək (baxmayaraq ki, bu qaranti deyil). Bu xəta “stack overflow” adlanır, çünki hər dəfə bir funksiyanı çağırdığınız zaman bəzi məlumatlar (əsasən funksiya arqumentləri və lokal dəyişənlər) stack yaddaşında saxlanılır. (Əgər "stack yaddaşı"nın nə olduğunu bilmirsinizsə, hələlik narahat olmayın.) C++ dilində adi funksiyalarla rekursiv funksiyalar arasında elə də böyük fərq yoxdur; funksiyalar mütləq öz daxilindəki digər funksiyaları çağıra bilər və bir funksiyanın özünü çağıra bilməməsi üçün heç bir səbəb yoxdur.

Tapşırıq 4. Məsələni həll edin: n tam ədədi verilir, 0, 1, . . ., n−1-in bütün permutasiyalarını çap edin(bu tapşırığı bir çox yolla yerinə yetirmək olar, lakin bu tapşırığı rekursiv funksiyalardan istifadə edərək necə yerinə yetirəcəyinizi öyrənmək tövsiyə olunur).

Qarşılıqlı Rekursiyalar​

Qarşılıqlı rekursiya adlanan bir şey də var. Bu, başqa bir g funksiyasını çağıran və eyni zamanda yenidən f-i çağıran bir f funksiyası təyin etdiyiniz zaman baş verir. Lakin, bunu C++ dilində tətbiq edərkən əvvəlcə funksiyalardan birini digərinə görünən şəkildə elan etməlisiniz. (Bu, int x = y; int y = x; yaza bilməməyinizə bənzəyir, lakin int y; int x = y; y = x; yaza bilərsiniz.)

Məsələn, gəlin aşağıdakı funksiyaları implement etməyə çalışaq:

F(n)={1if n=0n−M(F(n−1))if n>0F(n) = \begin{cases} 1 & \text{if } n = 0 \\ n - M(F(n-1)) & \text{if } n > 0 \end{cases}F(n)={1n−M(F(n−1))​if n=0if n>0​ M(n)={0if n=0n−F(M(n−1))if n>0M(n) = \begin{cases} 0 & \text{if } n = 0 \\ n - F(M(n-1)) & \text{if } n > 0 \end{cases}M(n)={0n−F(M(n−1))​if n=0if n>0​ 
#include <bits/stdc++.h>
using namespace std;

int M(int n);

int F(int n) {
    if (n == 0) return 1;
    return n - M(F(n - 1));
}

int M(int n) {
    if (n == 0) return 0;
    return n - F(M(n - 1));
}
int main() {
  cout << M(6) << ' ' << F(6) << '\n';
}

Maraqlı fakt: Bu funksiyalar “Hofstadter's Female and Male sequences” adlanır və bütün n qiymətləri üçün M(n) + F(n) = n + 1 şərti ödənir.
